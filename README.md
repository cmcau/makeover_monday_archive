# Makeover Monday Archiver

A script that walks a list of [data.world](https://data.world/makeovermonday) Makeover Monday datasets and archives each one into a clean, GitHub-ready folder structure — the data files **and** the full Summary section (text + images).

## What it produces

For a typical (data.world) week it creates:

```
output/
└── 2023/
    └── w01/
        ├── README.md      # the Summary / description, with images relinked to local copies
        ├── metadata.json  # raw dataset metadata from the data.world API
        ├── data/          # every data file (csv, xlsx, …)
        └── images/        # every image referenced in the Summary
```

The Summary's images are downloaded into `images/` and the `README.md` is rewritten to point at the local copies, so each week renders fully on GitHub with no external dependencies.

### Weeks that aren't on data.world

Not every challenge lives on data.world — some weeks point to a Maven Analytics challenge, a direct file, or a shortened link. The archiver reads the canonical week list from **makeovermonday.co.uk** and handles these automatically:

- **data.world** weeks → archived in full as above.
- **Direct file** links → the file is downloaded into `data/`.
- **External pages** (e.g. Maven, behind JavaScript) → a `README.md` is written capturing the title and every link (data, article, original source), plus a `MANUAL_DOWNLOAD_NEEDED.txt` marker. Drop the file into that week's `data/` folder by hand and it's done.
- **Shortened links** (bit.ly, etc.) are followed to their real destination first — most resolve back to data.world.

## Setup

1. Install the dependencies (`requests` and `beautifulsoup4`):

   ```bash
   pip install -r requirements.txt
   ```

2. Get a free data.world API token at <https://data.world/settings/advanced> (a read-only token is enough).

3. Provide the token one of three ways:
   - copy `.env.example` to `.env` and paste it in, **or**
   - set an environment variable: `export DW_AUTH_TOKEN=...` (Windows: `setx DW_AUTH_TOKEN ...`), **or**
   - pass it on the command line with `--token`.

## Usage

### Recommended: site-driven mode

Reads the master list from makeovermonday.co.uk, so every week is discovered with its real data link — no guessing slugs, and non-data.world weeks are handled too.

```bash
# Archive everything for one or more years from the master list
python download_makeovermonday.py --from-site --year 2023

# Archive all years the site knows about
python download_makeovermonday.py --from-site

# Preview what would be processed (shows each week's type and link)
python download_makeovermonday.py --from-site --year 2023 --dry-run
```

You can also inspect (or hand-edit) the master list first:

```bash
python fetch_links.py                 # writes links_master.csv + links_master.json
python download_makeovermonday.py --from-site --master-json links_master.json
```

### Manual modes

Still available if you'd rather drive it yourself with explicit data.world links:

```bash
# From an explicit list of links
python download_makeovermonday.py --links-file links.txt

# Auto-generate data.world slugs for a year (data.world weeks only)
python download_makeovermonday.py --year 2023 --weeks 1-52
```

### Options

| Flag | Purpose |
|------|---------|
| `--from-site` | Discover every week from the makeovermonday.co.uk master table (recommended). Handles data.world and non-data.world weeks. |
| `--master-json PATH` | Use a saved `links_master.json` instead of scraping live. |
| `--no-resolve` | With `--from-site`, don't follow shortened links. |
| `--links-file PATH` | Text file with one data.world URL per line (`#` comments allowed). |
| `--year YEAR [YEAR …]` | One or more years to generate links for. |
| `--weeks SPEC` | Weeks to generate, e.g. `1-52` or `1,3,5` or `1-10,20`. Defaults to `1-52`. |
| `--owner NAME` | data.world org for generated links (default `makeovermonday`). |
| `--output DIR` | Output root (default `./output`). |
| `--token TOKEN` | API token (overrides `DW_AUTH_TOKEN` / `.env`). |
| `--pause SECONDS` | Delay between requests (default `0.5`) to stay polite to the API. |
| `--overwrite` | Re-download files that already exist (default: skip). |
| `--dry-run` | Print the datasets that would be processed, then exit. |

## Regenerating the index

The archive index near the top of this file is built from whatever currently exists in `output/`. After downloading more weeks, rebuild it with:

```bash
python generate_index.py
```

It only rewrites the marked index section, leaving the rest of this README untouched.

## Notes

- **Resumable.** If a week's folder already exists, that week is skipped entirely up front — no metadata call, no downloads — so re-runs are fast and only missing weeks are fetched. Use `--overwrite` to force existing weeks to be re-fetched and refreshed.
- **Robust.** Requests are retried with back-off, rate limits (HTTP 429) are respected, and a single bad image or missing dataset is logged and skipped rather than aborting the whole run.
- **Folder naming.** The year and week are parsed from each dataset slug (e.g. `2023w1` → `2023/w01`). Anything that can't be parsed lands under `output/unsorted/`.

## Pushing to GitHub

Easiest: double-click **`setup_git.bat`** (or pass your repo URL):

```bat
setup_git.bat https://github.com/<you>/<repo>.git
```

It initializes the repo, double-checks `.env` is excluded, makes the first commit, wires the remote, and pushes. Equivalent manual steps:

```bash
git init
git add .
git commit -m "Archive Makeover Monday datasets"
git branch -M main
git remote add origin https://github.com/<you>/<repo>.git
git push -u origin main
```

## Automate (weekly auto-archive)

`archive_latest.bat` downloads any new weeks for the **current year** (skipping what you already have), regenerates the index, and — if you set `AUTO_PUSH=1` inside the file — commits and pushes the changes. It logs each run to `archive_log.txt`.

Test it once by double-clicking it, then schedule it via **Windows Task Scheduler**. This one-liner registers a weekly Tuesday-morning run (Makeover Monday datasets drop on Mondays):

```bat
schtasks /Create /SC WEEKLY /D TUE /ST 09:00 /F ^
  /TN "MakeoverMonday Archive" ^
  /TR "\"%USERPROFILE%\Documents\Claude\Projects\Makeover Monday rescue\archive_latest.bat\""
```

Adjust the path if you move the folder. Remove it any time with:

```bat
schtasks /Delete /TN "MakeoverMonday Archive" /F
```

> The scheduled job must run on this machine — the download needs your token and network access, so it can't run inside Cowork's sandbox.

The included `.gitignore` keeps your `.env` (and the token in it) out of the repo.
